## Кратко

Нужно подготовить в разделе `Network` подробную русскоязычную статью о протоколе OSPF: объяснить link-state-модель, установление соседства, распространение информации о состоянии каналов, построение LSDB и расчет кратчайших маршрутов алгоритмом SPF.

## Контекст

В разделе `Network` уже есть статья о distance-vector-протоколе RIP. Следующий материал должен показать, как устроен link-state-протокол OSPF, чем он отличается от RIP и почему лучше подходит для более крупных и сложных сетей.

Основной предмет статьи — OSPFv2 для IPv4. OSPFv3 для IPv6 нужно рассмотреть отдельно и кратко, чтобы читатель понимал назначение версий и ключевые различия.

## Обязательные технические элементы

- Указать, что OSPF является link-state IGP и использует IP protocol number 89, а не TCP или UDP.
- Объяснить, что все маршрутизаторы одной области должны иметь согласованное представление LSDB после сходимости.
- Показать последовательность: Hello → соседство → обмен LSA → синхронизация LSDB → расчет SPF → установка маршрутов.
- Описать требования к уникальности Router ID и способы его выбора.
- Объяснить, какие параметры должны совпадать для формирования соседства, включая area ID, Hello/Dead intervals, тип области, аутентификацию и совместимые сетевые параметры.
- Перечислить и объяснить состояния соседства OSPF без утверждения, что все соседи обязаны переходить в Full на multi-access-сегменте.
- Объяснить, что в broadcast-сети маршрутизаторы DROther обычно остаются в состоянии 2-Way друг с другом и формируют полную adjacency с DR/BDR.
- Показать правила выбора DR/BDR по interface priority и Router ID, а также отметить непредвыборный характер выборов.
- Привести формулу стоимости интерфейса и пояснить зависимость от reference bandwidth:

```text
cost = reference bandwidth / interface bandwidth
```

- Отметить необходимость согласованной настройки reference bandwidth на маршрутизаторах домена.
- Показать пример сравнения двух путей по суммарной стоимости.
- Объяснить назначение area 0 и требование логической связности остальных областей с backbone.
- Кратко описать LSA типов 1–5 и пояснить, что область их распространения различается.
- Не смешивать LSA type с типом маршрута в таблице маршрутизации.
- Указать multicast-адреса OSPFv2 `224.0.0.5` и `224.0.0.6` и пояснить их назначение.
- Указать multicast-адреса OSPFv3 `FF02::5` и `FF02::6`.
- Пояснить, что OSPFv2 предназначен для IPv4, а OSPFv3 первоначально разработан для IPv6; дополнительные возможности и расширения описывать с привязкой к источникам.
- Все значения таймеров подавать с учетом network type и реализации, не объявляя одно значение универсальным.

## Практический пример

Использовать топологию минимум из трех маршрутизаторов и двух областей:

```text
LAN-A — R1 — area 1 — R2 (ABR) — area 0 — R3 — LAN-B
```

Для примера необходимо:

- привести адресный план;
- назначить уникальные Router ID;
- показать базовую конфигурацию OSPF;
- проверить состояние соседей;
- показать маршруты OSPF в таблице маршрутизации;
- показать LSDB и определить основные LSA;
- вычислить стоимость одного маршрута вручную и сверить ее с результатом;
- показать изменение маршрута или состояния после отключения одного интерфейса;
- не использовать реальные пароли, публичные адреса организации или иные секреты.
