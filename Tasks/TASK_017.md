Подробное объяснение основных сущностей Kubernetes с воспроизводимыми примерами

## Статус

`done`

## Кратко

Нужно подготовить большой обучающий материал в разделе `Kubernetes`, который простыми словами объясняет основные сущности Kubernetes и показывает практические примеры, которые можно повторить руками в безопасном demo-namespace.

## Контекст

В wiki уже есть практические Kubernetes-runbook'и для конкретных операций, но не хватает базового материала, который объясняет фундаментальные сущности Kubernetes "на пальцах": зачем они нужны, как связаны между собой и что происходит при применении manifest'ов.

Материал должен быть полезен для самостоятельного повторения: читатель должен иметь возможность создать namespace, применить YAML, посмотреть состояние через `kubectl`, изменить объект, увидеть эффект и удалить все ресурсы после практики.

## Цель

Создать подробную русскоязычную инструкцию, по которой можно:

- понять, из каких основных сущностей состоит Kubernetes;
- увидеть связь между `Node`, `Namespace`, `Pod`, `ReplicaSet`, `Deployment`, `Service`, `Ingress` или `Gateway`, `ConfigMap`, `Secret`, `Volume`, `PV`, `PVC`, `StatefulSet`, `DaemonSet`, `Job`, `CronJob`;
- разобраться в labels, selectors, annotations и owner references;
- понять разницу между декларативным manifest'ом и текущим состоянием кластера;
- повторить простые примеры через `kubectl apply`, `kubectl get`, `kubectl describe`, `kubectl logs`, `kubectl exec`, `kubectl port-forward`;
- увидеть типовые ошибки и научиться читать события, статусы и логи;
- безопасно удалить все demo-ресурсы после выполнения.

## Объем

- Подготовить основной материал `Kubernetes/basic-objects.md`.
- Начать с короткой модели Kubernetes: control plane, worker nodes, API server, scheduler, controller manager, kubelet, container runtime.
- Объяснить `apiVersion`, `kind`, `metadata`, `spec`, `status`.
- Показать, как `kubectl apply` отправляет желаемое состояние в API server, а контроллеры приводят кластер к этому состоянию.
- Для каждой основной сущности дать:
  - простое объяснение "на пальцах";
  - зачем она нужна;
  - минимальный YAML;
  - команды применения и проверки;
  - что должно получиться;
  - типовые команды диагностики.
- Все примеры выполнять в отдельном namespace `k8s-basics-demo`.
- Использовать безопасные публичные образы вроде `nginx`, `busybox`, `redis` или `alpine`.
- Добавить cleanup-раздел с удалением namespace.
- Обновить `Kubernetes/README.md` ссылкой на новый материал.
- Обновить `TASK.md` и `LOG.md` при выполнении задачи.

## Вне объема

- Установка Kubernetes, Talos, Cilium, Helm, Argo CD или Ingress Controller.
- Глубокое описание CNI, CSI, CRI и сетевой модели на уровне реализации.
- Security hardening production workload'ов.
- Подробное описание CRD и операторов, кроме краткого объяснения, что это расширения API.
- Выполнение команд на живом рабочем кластере без явного выбора demo-контекста.

- Текущий context проверен командой `kubectl config current-context`.
- Пользователь понимает, что примеры нужно выполнять только в тестовом окружении.

## Предлагаемая структура материала

1. Что такое Kubernetes простыми словами.
2. Как читать YAML-объект: `apiVersion`, `kind`, `metadata`, `spec`, `status`.
3. Namespace как отдельная "песочница" для примеров.
4. Pod как минимальная единица запуска контейнера.
5. Labels и selectors как "наклейки" и поиск объектов.
6. ReplicaSet как контроллер нужного числа pod'ов.
7. Deployment как безопасное управление версиями приложения.
8. Service как стабильная точка доступа к pod'ам.
9. `kubectl port-forward` для локальной проверки.
10. ConfigMap для конфигурации без пересборки образа.
11. Secret для чувствительных значений с оговоркой про base64 и безопасность.
12. Volumes, PV и PVC для хранения данных.
13. StatefulSet на примере Redis или nginx с постоянным именем pod'а и PVC.
14. DaemonSet как запуск pod'а на каждой node.
15. Job и CronJob для одноразовых и регулярных задач.
16. Ingress и Gateway API как входящий HTTP/HTTPS-трафик в кластер.
17. Probes: `readinessProbe`, `livenessProbe`, `startupProbe`.
18. Requests и limits как заявка и ограничение ресурсов.
19. Events, logs, describe и базовая диагностика.
20. Cleanup всех demo-ресурсов.
21. Короткая карта: какую сущность выбирать для какой задачи.

## Примеры, которые нужно включить

- Создать namespace `k8s-basics-demo`.
- Запустить одиночный `Pod` с `nginx` и посмотреть logs/describe.
- Добавить labels и выбрать pod через `kubectl get pods -l app=demo`.
- Создать `Deployment` на 2 реплики и увидеть, как он создает `ReplicaSet` и pod'ы.
- Удалить один pod и показать, что Deployment создает новый.
- Сделать rolling update образа и посмотреть rollout history.
- Откатить Deployment через `kubectl rollout undo`.
- Создать `Service` `ClusterIP` и проверить доступ из временного `busybox` pod.
- Сделать `port-forward` на Service и открыть приложение локально.
- Передать настройки через `ConfigMap` в env и volume.
- Передать тестовый пароль через `Secret`, объяснив ограничения base64.
- Создать `PVC` и pod, который пишет файл в volume.
- Показать `Job`, который выполняется один раз и завершается.
- Показать `CronJob` с ручным запуском job из расписания.
- Показать базовую диагностику `ImagePullBackOff`, `CrashLoopBackOff` или неправильного selector.
