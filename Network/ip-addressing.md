# IPv4-адресация и быстрый расчет подсетей

IPv4-адрес состоит из 32 бит и обычно записывается четырьмя десятичными октетами:

```text
192.168.1.70
```

Маска или CIDR-префикс определяет, какая часть адреса обозначает сеть, а какая — узел внутри этой сети. CIDR (Classless Inter-Domain Routing, бесклассовая междоменная маршрутизация) использует запись вида `адрес/длина_префикса`, например `192.168.1.70/26`.[4]

Для быстрого ручного расчета большинства учебных и практических подсетей достаточно:

1. определить маску по префиксу;
2. найти изменяемый октет;
3. вычислить шаг сети;
4. найти диапазон, в который попадает IP-адрес;
5. определить адрес сети, broadcast и адреса хостов.

## Из чего состоит IPv4-адрес

В адресе четыре октета, в каждом по 8 бит:

```text
192      .168      .1        .70
11000000 .10101000 .00000001 .01000110
```

Всего:

```text
4 × 8 = 32 бита
```

Префикс `/26` означает:

```text
26 бит — сеть
 6 бит — хосты
```

Маска для `/26`:

```text
11111111.11111111.11111111.11000000
255.255.255.192
```

Единицы маски относятся к сетевой части, нули — к узловой.

## Основные понятия

Для обычной IPv4-подсети:

- адрес сети — первый адрес диапазона;
- broadcast — последний адрес диапазона;
- первый хост — адрес сразу после адреса сети;
- последний хост — адрес перед broadcast;
- префикс показывает количество сетевых битов.

Например:

```text
Сеть:            192.168.1.64/26
Первый хост:     192.168.1.65
Последний хост:  192.168.1.126
Broadcast:       192.168.1.127
```

В обычной broadcast-подсети адрес сети и broadcast не назначают устройствам. Исключения `/31` и `/32` рассмотрены отдельно ниже.

## Формулы

Для обычных IPv4-подсетей с префиксом от `/0` до `/30`:

```text
Битов узлов = 32 - длина префикса
Всего адресов = 2^(32 - длина префикса)
Обычных доступных хостов = 2^(32 - длина префикса) - 2
```

Для `/26`:

```text
Битов узлов = 32 - 26 = 6
Всего адресов = 2^6 = 64
Доступных хостов = 64 - 2 = 62
```

Формула `- 2` не применяется механически к `/31` и `/32`.

## Таблица популярных префиксов

| Префикс | Маска | Всего адресов | Обычных хостов | Шаг в последнем октете |
| --- | --- | ---: | ---: | ---: |
| `/24` | `255.255.255.0` | 256 | 254 | 256 |
| `/25` | `255.255.255.128` | 128 | 126 | 128 |
| `/26` | `255.255.255.192` | 64 | 62 | 64 |
| `/27` | `255.255.255.224` | 32 | 30 | 32 |
| `/28` | `255.255.255.240` | 16 | 14 | 16 |
| `/29` | `255.255.255.248` | 8 | 6 | 8 |
| `/30` | `255.255.255.252` | 4 | 2 | 4 |

Полезная последовательность значений октета маски:

```text
128, 192, 224, 240, 248, 252, 254, 255
```

Соответствующие размеры блока:

```text
128, 64, 32, 16, 8, 4, 2, 1
```

При увеличении префикса на единицу размер подсети уменьшается вдвое.

## Метод шага сети

Для не выровненного по границе октета префикса найдите частичный октет маски — значение между `1` и `254`. Например, для `/26` это `192`.

```text
Шаг = 256 - значение изменяемого октета маски
```

Для префиксов `/8`, `/16` и `/24` частичного октета нет: граница проходит между октетами. Все октеты узловой части нужно обнулить. Первый узловой октет занимает полный диапазон `0–255`, что условно соответствует шагу `256`; поэтому в таблице для `/24` указан именно такой шаг.

Для `/26`:

```text
Маска = 255.255.255.192
Шаг = 256 - 192 = 64
```

Границы подсетей в последнем октете:

```text
0, 64, 128, 192
```

Диапазоны:

```text
0–63
64–127
128–191
192–255
```

IP попадает ровно в один из этих диапазонов. Начало диапазона — адрес сети, конец — broadcast.

## Пример 1: `192.168.1.70/26`

### Шаг 1. Определяем маску

```text
/26 = 255.255.255.192
```

### Шаг 2. Рассчитываем размер блока

```text
256 - 192 = 64
```

### Шаг 3. Находим диапазон

Последний октет IP равен `70`. Он находится в диапазоне:

```text
64–127
```

### Результат для `/26`

| Параметр | Значение |
| --- | --- |
| Сеть | `192.168.1.64/26` |
| Маска | `255.255.255.192` |
| Первый хост | `192.168.1.65` |
| Последний хост | `192.168.1.126` |
| Broadcast | `192.168.1.127` |
| Всего адресов | 64 |
| Доступных хостов | 62 |

Проверка логики:

```text
64 адреса: 64–127
Минус адрес сети 64
Минус broadcast 127
Остается 62 адреса: 65–126
```

## Пример 2: `10.0.5.130/27`

### Маска и шаг для `/27`

```text
/27 = 255.255.255.224
Шаг = 256 - 224 = 32
```

Границы:

```text
0, 32, 64, 96, 128, 160, 192, 224
```

Последний октет `130` входит в диапазон `128–159`.

### Результат для `/27`

| Параметр | Значение |
| --- | --- |
| Сеть | `10.0.5.128/27` |
| Маска | `255.255.255.224` |
| Первый хост | `10.0.5.129` |
| Последний хост | `10.0.5.158` |
| Broadcast | `10.0.5.159` |
| Всего адресов | 32 |
| Доступных хостов | 30 |

## Пример 3: `172.16.10.77/20`

Здесь изменяется не четвертый, а третий октет.

### Маска и шаг для `/20`

```text
/20 = 255.255.240.0
Шаг = 256 - 240 = 16
```

Границы по третьему октету:

```text
0, 16, 32, 48, 64, 80, ...
```

Третий октет IP равен `10`, значит он входит в блок `0–15`.

### Результат для `/20`

| Параметр | Значение |
| --- | --- |
| Сеть | `172.16.0.0/20` |
| Маска | `255.255.240.0` |
| Первый хост | `172.16.0.1` |
| Последний хост | `172.16.15.254` |
| Broadcast | `172.16.15.255` |
| Всего адресов | 4096 |
| Доступных хостов | 4094 |

Почему broadcast заканчивается на `15.255`:

- третий октет выбранного блока занимает значения от `0` до `15`;
- четвертый октет внутри блока занимает значения от `0` до `255`;
- последний адрес всего блока — `172.16.15.255`.

## Быстрый способ найти начало блока

Если известен шаг, начало блока можно определить как ближайшее значение из последовательности, не превышающее нужный октет.

Для `130` при шаге `32`:

```text
0, 32, 64, 96, 128, 160
                ^
```

Ближайшая нижняя граница — `128`.

Эквивалентная формула:

```text
Начало блока = floor(значение октета / шаг) × шаг
```

Для `130`:

```text
floor(130 / 32) × 32 = 4 × 32 = 128
```

Конец блока:

```text
Broadcast-октет = начало блока + шаг - 1
128 + 32 - 1 = 159
```

## Как подобрать префикс под число устройств

Для обычной подсети сначала добавьте два служебных адреса:

```text
Требуемый размер = количество устройств + 2
```

Затем выберите ближайшую степень двойки, которая не меньше результата.

### Пример: 50 устройств

```text
50 + 2 = 52
```

Ближайший подходящий блок — 64 адреса:

```text
64 адреса = 2^6
32 - 6 = /26
```

Подсеть `/26` дает 62 обычных адреса хостов.

### Шпаргалка выбора

| Нужно хостов | Минимальный обычный префикс |
| ---: | --- |
| 2 | `/30` |
| 3–6 | `/29` |
| 7–14 | `/28` |
| 15–30 | `/27` |
| 31–62 | `/26` |
| 63–126 | `/25` |
| 127–254 | `/24` |

При проектировании стоит оставлять разумный запас, но слишком крупная подсеть увеличивает broadcast-домен и расход адресов.

## Особенности `/31`

Подсеть `/31` содержит два адреса:

```text
255.255.255.254
```

Обычная формула дала бы:

```text
2 - 2 = 0 хостов
```

Но RFC 3021 разрешает использовать оба адреса `/31` как адреса узлов на point-to-point (точка-точка) соединении, где есть ровно две стороны и нет необходимости в широковещательном адресе broadcast.[5]

Пример:

```text
10.0.0.0/31

Сторона A: 10.0.0.0
Сторона B: 10.0.0.1
```

Не следует автоматически применять `/31` к обычному Ethernet-сегменту с несколькими устройствами. Оба конца канала и используемое оборудование должны поддерживать такую адресацию.

## Особенности `/32`

Префикс `/32` описывает ровно один IPv4-адрес и используется как host route — маршрут к одному узлу.[4]

```text
192.0.2.10/32
```

Здесь нет отдельного диапазона хостов и broadcast внутри блока. `/32` часто используют для:

- loopback-адреса — внутреннего логического адреса маршрутизатора;
- точного маршрута к одному узлу;
- ACL (Access Control List, список контроля доступа) и правила, относящегося к одному адресу;
- объявления единственного адреса.

## Проверка с помощью Python

Стандартный модуль `ipaddress` помогает проверить ручной расчет:

```python
import ipaddress

interface = ipaddress.ip_interface("192.168.1.70/26")
network = interface.network
hosts = list(network.hosts())

print("Сеть:", network.network_address)
print("Маска:", network.netmask)
print("Broadcast:", network.broadcast_address)
print("Всего адресов:", network.num_addresses)
print("Первый хост:", hosts[0])
print("Последний хост:", hosts[-1])
```

Ожидаемый результат:

```text
Сеть: 192.168.1.64
Маска: 255.255.255.192
Broadcast: 192.168.1.127
Всего адресов: 64
Первый хост: 192.168.1.65
Последний хост: 192.168.1.126
```

Для очень большой сети не нужно преобразовывать `network.hosts()` в список: это может потребовать много памяти. Первый и последний адрес лучше вычислять напрямую или получать итератором.

## Типичные ошибки

### Путать адрес узла и адрес сети

```text
192.168.1.70/26 — адрес интерфейса
192.168.1.64/26 — адрес сети
```

### Всегда изменять четвертый октет

Для `/20` изменяемый октет — третий:

```text
255.255.240.0
        ^
```

### Забывать про broadcast

В обычной `/30` всего четыре адреса, но устройствам доступны только два.

### Прибавлять шаг к IP, а не к границе

Для `10.0.5.130/27` следующая сеть начинается не с `162`, а со `160`, потому что границы идут от нуля с шагом 32.

### Применять `2^h - 2` к `/31` и `/32`

Для point-to-point `/31` оба адреса могут быть адресами сторон, а `/32` обозначает один конкретный адрес.[4][5]

## Универсальный алгоритм

1. Запишите IP и префикс.
2. Преобразуйте префикс в маску.
3. Найдите изменяемый октет маски.
4. Рассчитайте `256 - значение октета`.
5. Выпишите границы с полученным шагом.
6. Найдите диапазон, содержащий IP.
7. Возьмите начало диапазона как адрес сети.
8. Возьмите конец диапазона как broadcast.
9. Для обычной подсети исключите эти два адреса из диапазона хостов.
10. Отдельно проверяйте семантику `/31` и `/32`.

## Краткая шпаргалка

```text
IPv4:             32 бита
Битов хостов:     32 - префикс
Всего адресов:    2^(битов хостов)
Обычных хостов:   всего адресов - 2
Шаг сети:         256 - изменяемый октет маски
Сеть:             первый адрес блока
Broadcast:        последний адрес блока
/31:              два адреса point-to-point
/32:              один адрес, host route
```
